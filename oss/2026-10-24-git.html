OSS EXPLORER / #002 · 2026-10-24

Git

差分の履歴管理だけではない。内容を識別子に変える「オブジェクトデータベース」の設計。

概要

Gitは分散型バージョン管理システム。各クローンが履歴をローカルに保持し、ブランチの作成、履歴の参照、変更の統合を行える。Linuxカーネル開発を背景に誕生し、現在は幅広いソフトウェア開発で使われている。

主な特徴

  • 分散型：通常のクローンは履歴とオブジェクトをローカルに保持し、オフラインでもコミットや履歴参照ができる。
  • スナップショット指向：コミットはファイルツリーの状態を参照し、同一内容のオブジェクトを再利用できる。
  • 軽量なブランチ：ブランチは基本的にコミットを指す参照として管理される。
  • 整合性検証：オブジェクトの内容に基づくハッシュで破損や意図しない改変を検出しやすい。ただし署名なしでは作成者の真正性までは保証しない。

使いどころ

ソースコードの変更管理、チーム開発のレビュー、リリースのタグ付け、ドキュメントの履歴管理、組み込みファームウェアのバージョン追跡など。巨大な生成物や頻繁に変化するバイナリはGit LFSやアーティファクト保管庫との使い分けを検討する。

技術Pickup：内容アドレス指定オブジェクトデータベース

Gitは履歴を単なる差分の連続として保存するのではなく、blob（ファイル内容）、tree（ディレクトリ構造）、commit（スナップショットと親コミット）などのオブジェクトを組み合わせて表現する。オブジェクトIDは型・サイズを含むデータから算出したハッシュに基づく。歴史的にはSHA-1を使い、SHA-256形式のリポジトリにも対応する。

ファイルのバイト列

同じ内容のファイルは、同じハッシュアルゴリズムを使うリポジトリ内で同じblob IDになるため、内容を共有できる。変更が発生すると、変更されたblobとそれを参照するtree、そして新しいcommitが作られる。変更されていないオブジェクトは再利用される。

なぜこの設計が優れているのか

  • 不変オブジェクト：既存オブジェクトを書き換える代わりに、新しいオブジェクトと参照を作る。
  • 構造共有：変わらないファイルの内容をコピーせず再利用できる。
  • 履歴の連結：commitが親commitを参照するため、履歴を有向非巡回グラフ（DAG）としてたどれる。
  • データと名前の分離：ブランチ名は動く参照、オブジェクトIDは内容に基づく識別子として役割を分離する。

これは組み込みの設定スナップショット、更新履歴、コンテンツアドレス型ストレージ、イミュータブルなデータ構造にも応用できる考え方。ただしGitのオブジェクト格納方式をそのままリアルタイム制御やフラッシュメモリ制約の厳しい環境に採用できるわけではない。

実際に確かめる

git init demo && cd demo
printf 'hello\n' > hello.txt
git add hello.txt
git commit -m "first commit"
git cat-file -p HEAD
git ls-tree HEAD
git cat-file -p HEAD:hello.txt

最初のコマンドでリポジトリを作成し、コミット後にcommit・tree・blobの内容を確認する。コミットにはユーザー名とメールアドレスの設定が必要な場合がある。

実装を読む

注目ファイルは object-file.c（オブジェクトの読み書き）と tree.c（treeオブジェクトの処理）。内容アドレス指定とオブジェクト型の扱いを追う入口になる。
