Zstandard (zstd)

圧縮率だけではない。「高速な復元」を重視して設計されたロスレス圧縮アルゴリズム。

概要

Zstandard（zstd）は、Meta（旧Facebook）で開発されたオープンソースの可逆圧縮アルゴリズムおよびツール群。C言語を中心に実装され、CLIツールとライブラリの両方が提供される。ログ、バックアップ、データ配信などで圧縮サイズとCPU時間のバランスを取りやすい。

特徴

  • 幅広い圧縮レベル：速度重視から圧縮率重視まで設定できる。
  • 高速な展開：多くの用途で高速な解凍を目指した設計。
  • 辞書圧縮：小さく似たデータを多数圧縮するときに、共通辞書を利用できる。
  • ストリーミング：データを分割して順次圧縮・展開できる。
  • フレーム形式：圧縮データにヘッダーやブロック構造を持つ。

使いどころ

アプリのログ保存、バックアップ、パッケージ配布、ネットワーク転送、組み込み機器のデータ保存など。組み込みでは辞書サイズ、展開時のワークメモリ、最大ウィンドウサイズ、CPU負荷を考慮する必要がある。

技術Pickup：LZ77 + エントロピー符号化

zstdは入力を繰り返しパターンに基づいて表現し、さらに出現頻度を利用して符号化する。概念的な流れは次のとおり。

入力バイト列
→
一致探索
LZ77系
→
Literal + Sequence
→
エントロピー符号化
→
圧縮ブロック

一致探索は既出データとの重複を見つけ、文字列をリテラル（生のバイト列）と、繰り返しを表すシーケンスに分解する。シーケンスは概念的に「リテラル長・一致長・オフセット」の組で表される。

その後、リテラルにはHuffman符号化、シーケンスの各要素にはFSE（Finite State Entropy） が用いられる場合がある。ブロックの種類や圧縮モードによっては非圧縮・RLEなども使われ、必ず両方式を適用するわけではない。

FSEが面白い理由

FSEは有限状態の遷移を使うエントロピー符号化方式で、頻出シンボルには平均して少ないビット数を割り当てられる。ビット単位の処理を効率化しつつ、確率分布に応じた圧縮を実現する。復号時は状態と入力ビットから次のシンボル・状態を求めるため、テーブル駆動の実装に向いている。

設計上の注目点は「重複を見つける処理」と「確率的に短く符号化する処理」を分離したこと。アルゴリズムの役割分担が明確で、速度と圧縮率を段階的に調整できる。

実行例

zstd -3 application.log -o application.log.zst
zstd -d application.log.zst -o restored.log

1行目は圧縮レベル3でファイルを圧縮し、2行目は展開する。標準のCLIに加え、C APIでは ZSTD_compress() と ZSTD_decompress() などを利用できる。

ソースコードを読む

  • lib/compress/ — 圧縮処理
  • lib/decompress/ — 展開処理
  • lib/common/ — 共通処理・エントロピー関連
  • lib/zstd.h — 公開C API
