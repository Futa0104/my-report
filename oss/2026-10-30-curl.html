curl / libcurl

イベント駆動の通信処理を支える転送ライブラリ。

概要

curlはURLによるデータ転送を行うCLIツールで、libcurlはC言語で利用できる転送ライブラリ。HTTP(S)、FTP(S)、SFTPなど複数プロトコルを扱う（対応はビルド構成による）。

主な特徴

  • CLIとライブラリの両方を提供
  • プロキシ、リダイレクト、TLS証明書検証、接続再利用に対応
  • easy APIによる簡単な転送とmulti APIによる複数転送を選択可能
  • OS・TLSバックエンドへの依存を抽象化

使いどころ

API通信の診断、CIでのダウンロード、組み込み機器のHTTPS通信、ファームウェア更新ファイルの取得、複数の外部APIとの通信など。組み込みでは証明書管理、タイムアウト、メモリ使用量を確認する。

技術Pickup：multi_socket API

Application event loop → libcurl multi_socket → 転送状態機械 → OS/TLS

libcurlは、複数の通信を単一のイベントループから駆動できる。アプリは CURLMOPT_SOCKETFUNCTION と CURLMOPT_TIMERFUNCTION で監視対象とタイマーを受け取り、準備が整ったとき curl_multi_socket_action() を呼び出す。タイマー満了時は CURL_SOCKET_TIMEOUT を渡す。

なぜ優れている？

アプリケーションのイベントループと通信プロトコルの状態管理を分離できる。転送ごとに専用スレッドを作らず、複数の通信を協調的に進行できる。これは組み込みの非同期I/O設計にも参考になる。ただしDNS解決方式やバックエンド次第でブロッキング処理が残る可能性はある。

実行例

curl -I https://example.com

HTTPレスポンスヘッダーを取得する。C言語での利用ではeasy APIから始め、イベントループ統合が必要になればmulti_socket APIを検討するとよい。
