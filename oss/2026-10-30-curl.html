01概要・基本情報・開発背景

curlはURLによるデータ転送を行うCLIツールで、libcurlはC言語で利用できる転送ライブラリ。HTTP(S)、FTP(S)、SFTPなど複数プロトコルを扱う（対応はビルド構成による）。

項目内容
初期開発Daniel Stenberg（curlの名称で1998年から）
実装言語C
ライセンスcurl license（MIT/X系の独自ライセンス）
対象Linux・Windows・macOS・組み込みOSなど

開発背景

ネットワーク上のデータをコマンドラインから取得するための小さなツールを起点に、複数の通信プロトコルに対応するツールと再利用可能なライブラリへ発展しました。 curlの歴史

02特徴・使いどころ

  • CLIとライブラリの両方を提供
  • プロキシ、リダイレクト、TLS証明書検証、接続再利用に対応
  • easy APIによる簡単な転送とmulti APIによる複数転送を選択可能
  • OS・TLSバックエンドへの依存を抽象化

API通信の診断、CIでのダウンロード、組み込み機器のHTTPS通信、ファームウェア更新ファイルの取得、複数の外部APIとの通信など。組み込みでは証明書管理、タイムアウト、メモリ使用量を確認する。

03主な機能・API

機能代表的なAPI・コマンド役割

05技術Pickup： multi_socket APIによるイベント駆動I/O

例えば、組み込み機器で複数のサーバーからデータを取得するとき、1件ずつ同期的に待つと、通信待ちの間に別の転送を進めにくくなります。転送ごとにスレッドを作る方式では、スレッドのスタックや同期処理などのコストも考慮しなければなりません。

取り上げる意義：multi_socket APIは、アプリケーション側のイベント監視とライブラリ側の通信状態管理を分離します。既存のイベントループへ非同期I/Oを組み込む設計の実例として注目します。multi interface

イベント駆動I/Oの仕組み

Application event loop → libcurl multi_socket → 転送状態機械 → OS/TLS

libcurlは、複数の通信を単一のイベントループから駆動できる。アプリは CURLMOPT_SOCKETFUNCTION と CURLMOPT_TIMERFUNCTION で監視対象とタイマーを受け取り、準備が整ったとき curl_multi_socket_action() を呼び出す。タイマー満了時は CURL_SOCKET_TIMEOUT を渡す。

イベントループとの連携

イベントアプリケーションの処理
ソケット監視の更新CURLMOPT_SOCKETFUNCTIONで通知された監視条件を登録
タイマーの更新CURLMOPT_TIMERFUNCTIONの通知に従いタイマーを設定
ソケット準備完了・タイマー満了curl_multi_socket_action()を呼ぶ
転送完了curl_multi_info_read()で結果を回収

実行例

curl -I https://example.com

実行結果の例（模擬出力、実際の通信結果ではない）

HTTP/2 200
content-type: text/html
content-length: 1256

-IはHEADリクエストを送り、レスポンスヘッダーを表示する。ステータス、ヘッダー、HTTPバージョンは通信先と実行環境によって異なる。この環境ではDNS解決ができなかったため、成功時の代表例を示している。

C言語での利用ではeasy APIから始め、イベントループ統合が必要になればmulti_socket APIを検討するとよい。

06設計から学べること

  • イベント監視とプロトコル状態の分離：アプリが監視を担当し、libcurlが転送状態を管理する。イベントループを通信ライブラリから切り離せる。
    実装・資料：lib/multi.c · multi interface
  • コールバックによる依存方向の制御：監視対象・タイマーを通知し、アプリの準備完了イベントで転送を進める。
    実装・資料：CURLMOPT_SOCKETFUNCTION · CURLMOPT_TIMERFUNCTION · curl_multi_socket_action()
  • 非同期処理の前提を把握する：転送ごとの専用スレッドは不要だが、DNS等のバックエンドによってブロックが残り得る。
    実装・資料：multi interface
